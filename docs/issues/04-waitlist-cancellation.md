# 04. Лист ожидания, отказ, автоматическое повышение

**Цель:** когда мест нет — лист ожидания; кто-то отказался — первый из листа
получает место и письмо с билетом.

**Зависит от:** 03  **Оценка:** 1.5 ч  **Доказывает:** P2

## Объём
- Регистрация в полное событие: статус `waitlisted` (уже следует из
  алгоритма 03) + письмо `waitlisted:{id}` с позицией и ссылкой отказа.
- Домен `cancel(deps, { manageToken })`, одна транзакция:
  1. `SELECT … FROM events WHERE id = $1 FOR UPDATE` (сериализация по событию);
  2. регистрация → `cancelled`, `cancelled_at`; если чекинена — CHECK (I4)
     отклонит, маппим в `409 already_checked_in`;
  3. письмо «отказ принят» `cancelled:{id}` (A7) — и из `confirmed`, и из
     `waitlisted`;
  4. если была `confirmed`: первый `waitlisted` по `queue_seq` →
     `confirmed` + письмо `ticket:{id}`; если листа нет —
     `seats_taken - 1`;
  5. `pg_notify`.
- Отказ после начала события разрешён (A11). Повторный отказ — идемпотентен
  (200, второго письма нет).
- `DELETE /api/tickets/:manageToken` (или `POST …/cancel`).
- `GET /api/tickets/:manageToken` возвращает позицию в листе ожидания.
- UI: `/t/:token` — статус («место ваше» / «вы N-й в листе ожидания» /
  «участие отменено»), кнопка «Отказаться» с подтверждением; публичная страница
  показывает «мест нет — встать в лист ожидания».

## Не входит
Стресс-тесты гонок (05).

## Критерии приёмки
- [ ] Сценарий в UI: лимит 1, A и B регистрируются, A отказывается по ссылке
      из письма → у A в Mailpit письмо «отказ принят», у B — письмо с
      билетом, страница B показывает код.
- [ ] P2 зелёный.

## Тесты
- **P2** (`proofs/p2-waitlist.proof.test.ts`);
- отказ ожидающего — без повышения; повторный отказ идемпотентен;
- каждый отказ ставит ровно одно письмо `cancelled`;
- после отказа тот же email регистрируется заново: новый код, новое письмо
  `ticket` (A4);
- отказ после начала → 200 с повышением; отказ чекиненного → 409.
