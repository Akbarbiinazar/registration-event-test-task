# 06. Экран чекина

**Цель:** на входе вводят код билета; билет проходит ровно один раз.

**Зависит от:** 03  **Оценка:** 1 ч  **Доказывает:** часть P5 («один раз»)

## Объём
- Домен `checkIn(deps, { eventId, code })`: нормализация кода (верхний
  регистр, Crockford-замены `O→0`, `I/L→1`, удаление пробелов и дефисов);
  условный `UPDATE … WHERE checked_in_at IS NULL AND status = 'confirmed'
  RETURNING` + `pg_notify`. Нет строки → отдельным запросом выяснить причину:
  `404 ticket_not_found` / `409 ticket_not_active` /
  `409 already_checked_in` (+ время).
- `POST /api/organizer/events/:id/checkins` (ключ организатора).
- UI `/o/:id/checkin`: большое поле ввода с автофокусом, Enter → результат
  крупным цветным баннером (зелёный / жёлтый «уже прошёл в 18:42» / красный),
  поле очищается для следующего гостя; последние 5 чекинов списком.

## Не входит
Live-счётчик (07), QR.

## Критерии приёмки
- [ ] Код из письма проходит; второй раз — «уже прошёл в HH:MM».
- [ ] Код с маленькими буквами и `O` вместо `0` проходит.
- [ ] Код с дефисом, как в письме (`XXXX-XXXX`), проходит.
- [ ] Код другого события — «не найден».

## Тесты
- 10 параллельных чекинов одного кода → ровно один успех (I3);
- коды ожидающего/отказавшегося → 409, чужого события и несуществующий → 404;
- прямой `UPDATE` чекиненного на `cancelled` → `check_violation` (I4);
- без ключа организатора → 401.
