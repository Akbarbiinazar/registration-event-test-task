# 09. Перенос события

**Цель:** организатор меняет дату — все участники (подтверждённые и в листе
ожидания) получают письмо.

**Зависит от:** 03  **Оценка:** 1 ч  **Доказывает:** P6

## Объём
- Домен `reschedule(deps, { eventId, startsAt })`, одна транзакция:
  `SELECT … FOR UPDATE`; та же дата → `200 { unchanged: true }`, без писем и
  без смены версии; в прошлом → `400` с сообщением «Нельзя перенести на
  прошедшее время» (A9); иначе `starts_at`, `schedule_version + 1`, затем
  outbox `rescheduled:{registration_id}:{schedule_version}` для `confirmed` и
  `waitlisted` («было → стало» в поясе события; разные тексты для участника и
  ожидающего — D3); `pg_notify`.
- `PATCH /api/organizer/events/:id` (`{ startsAt }`; название/описание —
  можно, без писем).
- UI на `/o/:id`: «Перенести» → поле даты/времени → подтверждение «N
  участникам уйдёт письмо» → сохранить. Подпись: «Участники получат письмо
  только при изменении даты». Ответ `unchanged` → сообщение «Дата не
  изменилась, письма не отправлены».

## Не входит
Отмена события целиком.

## Критерии приёмки
- [x] Перенос в UI → в Mailpit письма всем подтверждённым и ожидающим, у
      отказавшихся — нет.
- [x] Публичная страница и экран организатора показывают новую дату.
- [x] P6 зелёный.

## Тесты
- **P6** (`proofs/p6-reschedule.proof.test.ts`);
- перенос в прошлое → 400 с понятным сообщением; без ключа / с чужим ключом → 401;
- та же дата → 200 `unchanged`, версия и outbox без изменений;
- тексты писем участнику и ожидающему различаются; правка только
  названия/описания писем не ставит.
