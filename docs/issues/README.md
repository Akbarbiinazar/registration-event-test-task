# Слайсы

Каждый слайс — вертикальный: миграция → домен → HTTP → UI → тест, и после
него продукт работает от начала до конца в своём объёме. Один слайс = одна
сессия агента = минимум один коммит + запись в `docs/DEVLOG.md`.

## Порядок отсечения при нехватке времени

Режем сверху вниз — первым уходит то, что меньше всего влияет на
доказуемость поведения из ТЗ.

| Очередь | Что режем | Чем заменяем |
|---|---|---|
| 1 | Слайс 10 (Playwright E2E) | P5 уже открывает два SSE-потока по HTTP; ручной сценарий «две вкладки» в README |
| 2 | Список событий на главной (02) | Прямые ссылки после создания события |
| 3 | Ретраи и backoff в отправщике писем (03) | Одна попытка; ошибка пишется в `last_error`, строка остаётся в outbox |
| 4 | Форма переноса в UI (09) | Только API + пример `curl` в README; P6 остаётся |
| 5 | GitHub Actions (01) | Вывод `npm run check` в DEVLOG |
| 6 | Полировка UI во всех слайсах | Голая, но рабочая разметка |

**Не режем никогда:** тесты P1–P6, инварианты БД из `project_spec.md` §5,
слайс 11 (честное описание состояния — требование ТЗ). Если не успеваем
слайс из 03–09 целиком — он не делается наполовину: в README помечается
«не сделано» с причиной.
